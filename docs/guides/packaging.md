# Packaging

At a glance: Release artifacts and how they are built: the Windows MSI (app and server), the Linux AppImage (app), the server `.deb` and the Docker image. Install steps: [server-install.md](https://github.com/phabioo/uzume/wiki/Server-installation), [server-docker.md](https://github.com/phabioo/uzume/wiki/Server-in-Docker), [app.md](https://github.com/phabioo/uzume/wiki/Using-the-app).

Release artifacts and how they are built (PoC platforms: [07-poc-scope.md](../architecture/07-poc-scope.md); other platforms are planned, see [08-repo-and-open-points.md](../architecture/08-repo-and-open-points.md)): the Windows MSI for app and server (below), the Linux x86-64 app AppImage, the server `.deb` (package `uzume-server`; ships `/usr/share/doc/uzume-server/copyright` and `THIRD-PARTY-NOTICES.txt`; the raw server binaries on a release come with `LICENSE` and `THIRD-PARTY-NOTICES-hub.txt`; regenerate with `make notices`) and the systemd script ([server-install.md](https://github.com/phabioo/uzume/wiki/Server-installation)). the Linux app as an AppImage (see [Linux AppImage](#linux-appimage)). macOS is dropped (2026-10-11).

## Windows installer

One MSI for app, server or both: `packaging/windows/uzume.wxs` (WiX v5, [ADR 0021](../adr/0021-one-windows-installer.md), proposed). It replaced the Inno Setup script of FrameBeam (ADR 0007 D8, removed); the Inno migration shell was removed on 2026-10-11. Unsigned (SmartScreen warning).

- Built by the Windows CI job (`.github/workflows/ci.yml`) from the assembled package `dist\uzume-app` and the Windows server binary. Artifacts: `uzume-windows-x64-msi` (the MSI) plus the portable zip.
- Local build (Windows only: the WiX binder needs msi.dll; .NET SDK 6+; the script installs WiX 5.0.2 and its extensions): `pwsh packaging\windows\build-msi.ps1 -ProductVersion 0.0.0.1 -PackageDir dist\uzume-app -HubExe server\dist\uzume-server-windows-amd64.exe -OutFile dist\msi\uzume.msi`. Details: [packaging/windows/README.md](../../packaging/windows/README.md).

### Features, scope and properties

- Display names, shortcuts and dialogs say Uzume. The installed-system identity is Uzume too (service names, install folders, registry keys, ProgramData folders, markers, AppUserModelId `Uzume.App`). The MSI keeps the UpgradeCode, so it replaces an installed FrameBeam product, but it does not take over the old app data folder: the app is paired again ([ADR 0030](../adr/0030-one-app-one-server-uzume.md)).
- Dialogs (design 8l, [runs-and-server.md](../design/uzume/runs-and-server.md#8l-windows-installer)): Welcome, licence, **How will you use Uzume?** with three options (Uzume = app only, per user, no administrator rights; Uzume with a server on this PC = app and server, per machine; Only the server = server, per machine), destination folder (shown, fixed by the option), server options (port, share in the home network; internet sharing is set up later in the app), ready, progress, finish. The finish page starts Uzume (checkbox), or for "Only the server" opens an elevated PowerShell window with `uzume-server setup-code` (address, security code, setup code; one UAC prompt; the code is not written to a file or the MSI log). Maintenance offers Repair and Remove only (`ARPNOMODIFY`: the scope of an installed product cannot change, so switching options is remove and install again). Remove of an install with the server asks whether to **also delete all server data**. Not built: the "port in use" check before installing (8L-11, it needs a custom action DLL; a server that cannot bind keeps its startup fallbacks) and the FrameBeam upgrade dialog (8L-10, no migration, ADR 0030).
- Features `Player` and `Hub`. A silent install without properties is app only, per user, in `%LOCALAPPDATA%\Programs\Uzume` (portable `data\` stays writable, [ADR 0004](../adr/0004-player-portable-data.md)).
- `INSTALL_HUB=1` installs per machine (`ALLUSERS=1`): app in `%ProgramFiles%\Uzume\App`, server in `%ProgramFiles%\Uzume\Server`. `INSTALL_PLAYER=0` with `INSTALL_HUB=1` is server only. Other properties: `HUB_PORT` (default 8443), `NETWORK_SHARING` (1 server only, 0 app plus server), `DESKTOP_SHORTCUT`, `REMOVE_SERVER_DATA=1` (on uninstall: also delete `%ProgramData%\Uzume\Server` and `ServerUpdater`; never on upgrades), `IMPORT_SERVER_DATA=<folder>` (with the server: before the service starts, `uzume-server import-data --from <folder>` copies the per-user server of "Only on this PC" into the service's data folder; it refuses to overwrite an existing server database, and a failure rolls the install back; set by "Share with others" in the app, ADR 0030 D6).
- Example: `msiexec /i uzume.msi /qn ALLUSERS=1 INSTALL_HUB=1 HUB_PORT=8443 NETWORK_SHARING=1`.
- Server: services `UzumeServer` (`NT SERVICE\UzumeServer`) and `UzumeServerUpdater` (LocalSystem), data `%ProgramData%\Uzume\Server`, updater folder `%ProgramData%\Uzume\ServerUpdater` (SYSTEM and Administrators only), two firewall rules for `uzume-server.exe`, registry `HKLM\Software\Uzume\Server` (`Port`, `InstallDir`).
- Markers next to the executables: `uzume-server.msi-installed`, `uzume-app.msi-installed` (self-update allowed). Package layout, notices and licenses as before: launcher `Uzume.exe`, `THIRD-PARTY-NOTICE.txt`, `LICENSE.txt`, `licenses\` at the top, the real app, `uzume-server.exe` (started by the app as a child process for "Only on this PC", ADR 0030 D6; no service, no firewall rule; also in the portable zip), DLLs, plugins and qml in `bin\`, data in `data\`. A server install puts a second copy in `%ProgramFiles%\Uzume\Server` for the service.
- Uninstall keeps `data\` (ROM cache, profiles, saves) and the server data in ProgramData, unless `REMOVE_SERVER_DATA=1` (or the box in the Remove dialog) deletes the server data.

### Migration and upgrades

- A per-machine install removes the per-user MSI product (`HKCU\Software\Uzume\App\ProductCode`) asynchronously, after about 15 s. MajorUpgrade handles later versions.
- The CI job installs silently, plants an old layout plus `data\marker`, upgrades and checks the result, runs `uzume-server setup-code` on a server-only install (the finish page command) and checks that a plain uninstall keeps the server data and `REMOVE_SERVER_DATA=1` deletes it. The dialogs themselves are only checked by the ICE validation of the build. Known limitations: [ADR 0021](../adr/0021-one-windows-installer.md).

## Linux AppImage

`Uzume-<version>-x86_64.AppImage`: one file for the app on Linux x86-64 (glibc 2.38 or newer, built on Ubuntu 24.04), attached to every beta prerelease and listed in the signed update index (`linux-x64`, kind `appimage`). An AppImage, not a Flatpak: the app starts its bundled `uzume-server` as a child process for "Only on this PC", loads libretro cores from its data folder and opens gamepads through SDL3/udev, none of which fits a sandbox, and one file can be replaced by the signed updater. Unsigned. Install and Steam Deck: [app.md](https://github.com/phabioo/uzume/wiki/Using-the-app#install).

- Contents: `usr/bin/uzume`, `uzume-cli`, `uzume-server`; Qt 6.4 with the QML modules of `client/ui`, the platform plugins xcb and wayland, imageformats, the TLS (OpenSSL) and FFmpeg multimedia backends; SDL3, libdatachannel, FFmpeg, Opus and their libraries. Not in the image: emulator cores (the build fails on any `*_libretro.*` file or `cores` directory), ROMs, BIOS. `usr/share/doc/uzume/` holds `LICENSE`, the notices and the copyright files of the bundled libraries. System libraries of the base system (glibc, GL, X11/Wayland client libraries) are not bundled.
- `AppRun` (`packaging/linux/appimage/AppRun`) sets `UZUME_DATA_DIR` to `$XDG_DATA_HOME/Uzume/Uzume` (`~/.local/share/Uzume/Uzume`) unless it is set, because the image itself is never a place for data (the extract-and-run mode, used without FUSE, unpacks to a writable temporary folder where the portable `data` folder would be lost), and selects the FFmpeg multimedia backend.
- Built by the CI job `app-appimage` (`.github/workflows/ci.yml`; artifact `uzume-app-linux-x64`: the AppImage and `player-release-info-linux.json`). Tools (linuxdeploy, its Qt plugin, appimagetool) are pinned with checksums in `scripts/appimage-tools.pin` and fetched by `scripts/fetch-appimage-tools.sh` into `~/.cache/uzume/tools/appimage`. The smoke test runs `--version-json`, checks the unpacked image for unresolved libraries and cores, runs the bundled server, and starts the GUI offscreen and under Xvfb with a temporary home.
- Local build: `cmake --preset linux-release` in `client/` (`CMAKE_PREFIX_PATH` from `make fetch-deps`, `SDL3_ROOT` from `make fetch-sdl3`; see [development.md](../development.md)), build `uzume_app` and `uzume_cli`, `make build-hub`, then `make package-app-appimage APP_VERSION=21.1.0`. Details: [packaging/linux/appimage/README.md](../../packaging/linux/appimage/README.md).
